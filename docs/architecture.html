01 — O que é

Visão Geral

Illusion of Dawn é um RPG de ação com visão de cima, estilo Zelda. Roda no navegador e também como aplicativo desktop (Windows e Mac). Todo o áudio e a maioria das texturas são gerados por código — não há arquivos de som ou imagem para os personagens e tiles base. A única exceção são os assets visuais do Tiled (spritesheet e PNGs externos).

O mapa do mundo é editado no Tiled Map Editor e sincronizado para o jogo com um único comando. Colisão, visuais decorativos e tipos de terreno vivem em layers separadas dentro do mesmo arquivo.

04 — Arquivos raiz

main.ts & constants.ts

main.ts

O primeiro arquivo executado. Inicializa o Phaser com resolução 1000×800 px, pixel art ativado, física arcade sem gravidade (top-down) e registra todas as cenas na ordem correta. É o único lugar onde o Phaser.Game é criado.

constants.ts

Repositório central de todos os valores numéricos e configurações usados em mais de um lugar. Se um número aparece em dois arquivos diferentes, ele deve estar aqui.

ConstanteValorO que define
TILE_SIZE32Tamanho de cada tile em pixels
MAP_COLS / MAP_ROWS64 / 48Dimensões do mapa mundial
SOLID_TILESSet<number>Quais tipos de tile colidem — fallback quando não há layer Collision no Tiled
CASTLE_DOOR_WX/WY27.5 / 26.0Posição da porta do castelo no mundo
WORLD_W / WORLD_H2048 / 1536 pxTamanho total do mundo em pixels
05 — Telas

Cenas src/scenes/

BootScene.ts 1292 linhas

Primeira cena. Não mostra nada jogável — carrega todos os PNGs externos e gera todas as texturas procedurais do jogo via código (personagens, paredes, HUD, clima). Quando termina, inicia CharacterSelectScene.

CharacterSelectScene.ts 483 linhas

Tela de seleção com três cards (Knight, Bard, Cleric). Salva a escolha no registry e inicia GameScene.

GameScene.ts 702 linhas

Cena principal. Monta as três layers do mapa (Ground, Decor, Collision), cria o player, spawn de 27 inimigos + boss, combate, clima, Dark Realm e transições.

UIScene.ts 491 linhas

Roda em paralelo. Exibe HUD: corações, barra de especial, HP do boss, portrait. Só lê dados via registry — nunca acessa GameScene diretamente.

CastleScene.ts 230 linhas

Interior do castelo com mapa hardcoded (24×18 tiles). Desbloqueia o Dark Realm na primeira visita. Porta de saída volta para GameScene.

GameOverScene.ts 95 linhas

Tela exibida quando o player morre. Botão para reiniciar na seleção de personagem.

VictoryScene.ts 102 linhas

Tela de vitória após derrotar o Mind Devourer. Animação e créditos.

07 — Sistemas

Sistemas src/systems/

AudioSystem.ts 332 linhas

Gera todo o áudio proceduralmente via Web Audio API — não há arquivos de som. Sintetiza efeitos (swing, hit, morte) e músicas de fundo distintas para GameScene e CastleScene.

SaveSystem.ts 26 linhas

Salva e lê dados persistentes no localStorage (ou disco no Electron). Guarda se o Dark Realm foi desbloqueado e o personagem escolhido.

WeatherSystem.ts 153 linhas

Controla o clima do mundo: sol, chuva e neve. Tipo muda aleatoriamente com o tempo. Partículas geradas proceduralmente — nenhum sprite externo.

08 — Utilitários

Utilitários src/utils/

iso.ts — Coordenadas e colisão

O coração do sistema de movimento. Toda entidade do jogo usa essas funções.

FunçãoO que faz
setCurrentMap()Registra o mapa ativo. Toda cena chama isso no create() para que isWall() saiba onde há paredes.
isWall(wx, wy)Retorna true se a posição é sólida. Usa a layer Collision do Tiled se existir; fallback para SOLID_TILES em cenas hardcoded.
moveSlide()Move uma entidade com deslize suave nas paredes — se X colide mas Y não, o personagem escorrega lateralmente.
worldDist()Distância entre dois pontos em coordenadas de mundo (tiles).
Mudar iso.ts afeta o movimento de tudo — player, inimigos, boss, projéteis. Todas as entidades usam moveSlide() para se mover.

sceneHelpers.ts — Setup de cenas

Funções repetidas em toda cena nova. Evita duplicação de código.

FunçãoO que faz
createPlayer()Lê o registry para saber qual personagem foi escolhido e instancia a classe correta (Player, Bard ou Cleric).
setupSceneInput()Configura teclado (WASD, Z, X, Q, E, R, Esc) e retorna as referências de teclas.
setupFollowCamera()Faz a câmera seguir o player com zoom 2.5× e limites do mundo.

config/TilesetGrass.ts — Frames de grama

Tabela de quais frames do tileset-grass.png usar para cada combinação de bordas (bitmask de 4 bits = 16 variações). Usado pelo GameScene.buildTileMap() para renderizar transições suaves entre grama e água.

10 — Editor de mapas

Tiled tiled/

ArquivoO que é
map.tmjMapa principal editável no Tiled Map Editor. Fonte da verdade — sempre editar aqui.
tileset-types.tsjDefine os 14 tipos de tile lógicos (grass, wall, water, etc.) com propriedades solid/walkable.
map.tsxDefine o tileset visual (PathAndObjects.png). Usado na layer Decor.
sprite.tmxArquivo auxiliar do Tiled para visualizar sprites isolados.

As três layers do mapa

Ground

Tipos de terreno (grass, wall, water, path…). Define o que o jogo trata como chão base. Usa só o tileset tileset-types.

Decor

Visuais decorativos de obstáculos (paredes, árvores, objetos). Usa o tileset map.tsx / PathAndObjects.png. Puramente visual — sem colisão.

Collision

Define quais tiles bloqueiam o movimento. Qualquer tile pintado aqui = sólido. Se esta layer não existir, o jogo usa o fallback SOLID_TILES.

Fluxo de edição

# 1. Editar o mapa
Abrir tiled/map.tmj no Tiled Map Editor

# 2. Sincronizar com o jogo
npm run sync-map   ↳ copia map.tmj → public/assets/map.json

# 3. Testar
npm run dev        ↳ abre http://localhost:3000

13 — Como as peças se falam

Comunicação entre Sistemas

Tiled Map Editor edita map.tmj
sync-map →
public/assets/map.json Ground + Decor + Collision
GameScene playerHP, bossHP, specialReady…
registry ⟷
UIScene lê e exibe no HUD
Qualquer cena chama setCurrentMap()
iso.ts →
Todas as entidades usam isWall() / moveSlide()
Regra de ouro da comunicação: UIScene nunca acessa GameScene diretamente. GameScene nunca acessa UIScene diretamente. O registry é o canal exclusivo entre elas. Isso permite trocar uma sem quebrar a outra.
14 — Convenções

Regras de Ouro

01

Texturas procedurais ficam em BootScene.ts. Todo generateTexture() vai lá — nunca em GameScene ou EntityScene.

02

Números mágicos ficam em constants.ts. Nada de 32 ou 4.5 espalhado pelo código.

03

UIScene nunca acessa GameScene. Comunicação exclusivamente via registry.

04

Colisão vem da layer Collision do Tiled. Se não existir, usa SOLID_TILES como fallback (cenas hardcoded como o castelo).

05

Visuais de obstáculos vêm da layer Decor. O buildTileMap() só renderiza o chão base — paredes e árvores são do Tiled.

06

Nunca editar map.json diretamente. Sempre editar tiled/map.tmj e rodar npm run sync-map.

07

Toda cena chama setCurrentMap(). Esquecer isso causa colisão do mapa anterior na cena nova.

08

Todo movimento usa moveSlide(). Mudar essa função afeta player, inimigos e boss ao mesmo tempo.
